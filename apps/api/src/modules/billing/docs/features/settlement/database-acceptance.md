## Uncertain outcomes, stop conditions and cleanup proof

Stop immediately for target/reservation/source drift, unexpected workload/data/schema/history, material runner defect, assertion or lock-observation failure, idle/child failure, timeout, migration/commit ambiguity or ownership/cleanup mismatch. No automatic rerun, new key, migration retry, gate relaxation, broad deletion, sequence reset, DROP/TRUNCATE or history edits. Known case failures permit only normal already-authorized owned cleanup after all contenders terminate and ownership is proven.

If settlement response is lost, retain the original request/key. Under later authorized reconciliation, query known order with current authorization and independently inspect scoped key/order: a saved matching aggregate proves commit; conflicting content or multiple rows stops. An absent read while writer is still active does not prove rollback. Resolve writer termination and transaction outcome before one explicitly permitted replay with the same key/content. Connection failure alone is never evidence of rollback. B02 models lost response by discarding a known committed result; actual transport loss/ambiguous COMMIT is an evidence gap unless separately instrumented and reviewed.

On migration uncertainty, perform no fixtures or migration retry. Retain ledger/report and stop for separately authorized read-only reconciliation of exact history plus catalog: only complete pre-0006 or complete post-0006 is recognizable; partial/mismatched state requires owner decision. Do not repair history or drop objects. Unknown financial/setup outcome similarly requires reconciliation authorization; do not erase evidence during cleanup.

Cleanup design: after all transactions/child terminate, reconnect only to approved fingerprint, acquire Access lock, compare every fixture row against the exact owned ID/scope/digest set (including planned setup identities if commit response was lost). Compare all twenty-table counts against owned rows; reject unknown/missing/changed ownership, foreign references or unexpected binding/policy rows. Mutable fixture digests must be updated from each verified intentional case, never accepted merely because an ID matches. Roll back cleanup on any mismatch.

Delete only proven owned rows in FK order: settlements and policy/history/display-history; Kitchen must already be empty; captured orders/policy and Menu children/parents; sessions/access reservations/grants/accounts; installation binding; branches/businesses. Derive exact FK ordering from verified snapshot before implementation; no unconstrained DELETE or cascade assumption. Commit cleanup, then independent read-only verification: all twenty application tables zero; seven exact migration entries, catalog/constraints/defaults intact; no active child/case transactions or idle errors. Sequence advances need not reset. Retain ledger, source hashes and safe report even on success; failure says cleanup failed/unknown, never clean. Cleanup-helper set equality is offline admission only, not SQL ownership proof.
